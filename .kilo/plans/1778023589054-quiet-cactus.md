# Fix: Infinite Skeleton Loading on Portfolio Reload

## Problem Description

- **First visit**: Portfolio cards load correctly via GraphQL fetch.
- **Subsequent reloads**: Only skeleton loading cards appear indefinitely; actual content never renders.
- This occurs because `PortfolioManager` does not populate the in-memory `portfolioCache` when reading from `sessionStorage`, creating a race condition where the `portfolioReady` event can be missed by `portfolio-grid.js`, leaving its initialization promise pending forever.

## Root Cause Analysis

1. `PortfolioManager.fetchPortfolioData()` reads from `sessionStorage` on cache hit but **does not set** the in-memory variable `portfolioCache`.
2. This causes `PortfolioManager.getState().cached` to return `false` even though valid data exists in `sessionStorage`.
3. `portfolio-grid.js`'s `loadPortfolioData()` sees `state.cached === false` and waits for a `portfolioReady` event.
4. If `PortfolioManager.init()` completes and dispatches the event **before** `portfolio-grid` registers its listener (possible due to microtask timing on cache-hit), the event is missed and the promise never resolves → infinite skeleton.

## Solution

Set `portfolioCache` synchronously when serving data from `sessionStorage` so that:

- `getState().cached` correctly reports `true`.
- `portfolio-grid.js` will use the `getAll()` path, which returns a resolved promise with the cached data immediately.
- Even if the event is missed, the direct cache path works.

## Implementation Steps

1. **File to modify**: `shared/components/portfolio/portfolio-manager.js`
2. In function `fetchPortfolioData(forceRefresh = false)`, locate the cache-hit branch:

   ```javascript
   if (Date.now() - timestamp < CONFIG.CACHE_TTL) {
     console.log("[PortfolioManager] Cache hit");
     return parsed.data;
   }
   ```

3. Add assignment to `portfolioCache` before returning:

   ```javascript
   if (Date.now() - timestamp < CONFIG.CACHE_TTL) {
     console.log("[PortfolioManager] Cache hit");
     portfolioCache = parsed.data; // Populate in-memory cache
     return parsed.data;
   }
   ```

4. No other changes needed.

## Validation

- Clear `sessionStorage` → visit page → GraphQL fetch occurs → cards load.
- Reload page → skeleton appears briefly then cards load instantly (from sessionStorage + in-memory cache).
- No console errors; `portfolioReady` event may be ignored but not needed.
- Test on multiple browsers to ensure consistent behavior.

## Risk Assessment

- **Low risk**: Simple one-line change, no new dependencies.
- Existing flow unchanged; only improves cache consistency.
- `portfolioCache` will be set earlier, making subsequent `getAll()` calls instantaneous.
